## 발견 사항

### 높음 — 임의의 비어 있지 않은 토큰으로 인증 우회

[auth.py](/tmp/oo-97eae653a45f-mtej4eps/workspace/auth.py:2)에서 토큰값의 일치 여부가 아니라 존재 여부만 검사합니다.

```python
return user_role == "admin" or bool(supplied_token)
```

`expected_token`은 전혀 사용되지 않습니다. 따라서 일반 사용자도 `"wrong"`, `"0"` 등 아무 문자열이나 제출하면 접근이 허용됩니다. 로컬에서 다음 결과를 재현했습니다.

```text
can_access("user", "wrong", "secret") => True
```

권장 개선:

- `supplied_token`과 `expected_token`을 실제로 비교합니다.
- 토큰이 비밀값이라면 `hmac.compare_digest()` 같은 상수 시간 비교를 사용합니다.
- 설정 누락으로 양쪽이 빈 문자열일 때 허용되지 않도록 `expected_token`의 비어 있음도 거부합니다.
- 관리자 무토큰 접근이 의도된 정책이 아니라면 `user_role == "admin"` 예외도 제거해야 합니다.

### 테스트 누락

[tests/test_auth.py](/tmp/oo-97eae653a45f-mtej4eps/workspace/tests/test_auth.py:8)는 빈 토큰 거부만 확인하므로 위 우회를 탐지하지 못합니다. 최소한 다음 사례가 필요합니다.

- 올바른 토큰 허용
- 잘못된 비어 있지 않은 토큰 거부
- 빈 `expected_token` 거부
- 관리자 무토큰 정책의 명시적 확인

현재 테스트 2개는 모두 통과하지만 보안 동작을 충분히 검증하지 않습니다.

추가로 `user_role`이 요청자가 직접 제공하는 값이라면 `"admin"` 문자열만으로도 우회할 수 있습니다. 다만 저장소에 호출부가 없어 역할값의 신뢰 경계를 확인할 수 없으므로 조건부 위험으로 남깁니다.
