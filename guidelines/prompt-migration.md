# 프롬프트 변경과 프론티어 모델 이행

## 목적

모델 교체와 지침 변경의 효과를 구분하면서, 필요한 것을 잃지 않는 가장 단순한 실행 경로를 찾는다. 전역 철학·행동 권한·중단 조건은 `AGENTS.md`가 원본이다.

프롬프트에는 결과, 성공 기준, 안전·권한·증거 제약, 맥락 의존 도구 라우팅, 출력 형식, 중단 조건만 남긴다. 결과를 정의한 뒤 모델이 경로를 선택하게 하되 필수 검증과 선택 가능한 절차를 구분한다.

## Astra 기준

확인일: 2026-09-05. 적용할 때 공식 문서와 활성 런타임을 다시 확인한다.

- 공식 모델 ID는 `gpt-6-astra`다. reasoning effort는 `low`, `medium`, `high`, `xhigh`, `max`를 지원한다.
- 명목 컨텍스트는 1,050,000토큰이고 최대 출력은 128,000토큰이다. 둘은 별개다.
- 272K를 초과하는 입력은 Astra API에서 요청 전체의 입력·캐시 단가가 2배, 출력 단가가 1.5배가 된다. 이 키트는 비용 효율을 위해 확장 컨텍스트를 요청하지 않는다.
- 기본 컨텍스트에 맞지 않는 작업은 컨텍스트를 늘리지 말고 입력·도구 출력을 줄이거나 작업 단위를 나눈다. 긴 번역은 필요하면 의미 단위로 분할하고, 큰 코드 변경은 TCA 등으로 검토 가능한 단위로 나눈다.
- 모델 교체만으로 도구 호출의 동시성, 같은 워킹트리의 writer/reader 안전 경계, 권한을 바꾸지 않는다.

1차 출처: [모델 사양](https://developers.openai.com/api/docs/models/gpt-6-astra), [모델 이행 가이드](https://developers.openai.com/api/docs/guides/latest-model).

## 기본 모델 배치

전역 지침은 모델 중립적으로 유지한다. 역할별 기본 후보만 스킬에 둔다.

- 주 세션: 현재 사용자가 선택한 모델과 설정을 따른다.
- 경계가 명확한 구현 worker: `software-engineering`의 Luna Max + Fast 우선 후보를 유지한다.
- CRA 독립 리뷰: `gpt-6-astra` + `medium` + standard tier를 기본으로 한다. Astra는 Sol보다 단가가 높으므로 실제 완료당 비용이 개선되는지는 대표 작업으로 확인한다.
- 모든 역할은 런타임 기본 컨텍스트를 사용한다. 키트는 `model_context_window`나 `model_auto_compact_token_limit`을 늘리는 override를 만들지 않는다.

## 간소화 원칙

1. 한 계약의 원본은 하나만 둔다. 다른 문서는 링크하거나 필요한 경계만 요약한다.
2. 모델의 과거 한계를 방어하기 위한 고정 청킹, 반복 조회, 과도한 작업표는 실제 실패 근거가 없으면 제거한다.
3. 검증은 변경된 계약에 가까운 범위부터 시작하고 공유 의존성·위험·불확실성이 요구할 때 넓힌다.
4. 실행 코드의 테스트는 공개 계약, 실제 안전 경계, 재발 가능한 회귀를 보호할 때만 유지한다. 특정 Markdown 문구·제목·예시를 고정하는 테스트는 만들지 않는다.
5. 일회성 행동 평가의 raw trace, grader 출력, 임시 실행 로그, 과거 의사결정 설명은 저장소에 장기 보존하지 않는다. 필요하면 PR·CI·별도 일시적 artifact에 남기고, 현재 동작은 현재 지침과 테스트가 설명한다.
6. 이미 유효한 근거는 대상과 조건이 그대로이고 회수 가능할 때 재사용한다. 변경·근거 소실·최신성 영향이 있으면 다시 확인한다.

## 변경과 검증

1. 고정 commit, 실제 로드된 지침·스킬, 모델·effort·런타임을 기준선으로 기록한다.
2. 모델 교체 효과를 보려면 기존 지침을 새 모델에서 먼저 평가한다.
3. 모델, 프롬프트, 도구 집합, effort를 한꺼번에 바꾸지 않는다.
4. 같은 입력과 판정 기준으로 비교하고 실제 산출물·trace를 본다. 정적 검사 통과를 행동 개선으로 표현하지 않는다.
5. 행동 비교가 실제 의사결정을 바꾸지 않는 작은 문서 변경에는 상시 회귀 세트를 만들지 않는다. 중요한 변화에서만 대표 사례를 선택해 실행하고 결과는 PR에 요약한다.
6. 회귀가 있으면 실제 실패를 고치고 영향을 받은 검사를 반복한다.

`python3 scripts/validate_kit.py`는 실행 코드와 기계 판독 계약을 검증한다. 없는 측정치나 미실행 행동 평가는 성공값으로 채우지 않는다.
