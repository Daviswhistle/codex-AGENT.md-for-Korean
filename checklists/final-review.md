# 최종 검토 체크리스트

- 요청한 산출물이 실제로 존재하는가
- 제목, 날짜, 파일명이 요청과 일치하는가
- 누락된 섹션이 없는가
- 숫자와 고유명사를 다시 확인했는가
- 링크가 살아 있는가
- 형식 요구가 지켜졌는가
- 기계 검색으로 잡을 수 있는 오류를 검색했는가
- 선행 명령 실패로 실행되지 않은 뒤쪽 확인을 통과한 것으로 오인하지 않았는가
- 사람이 읽어야 하는 어색함을 다시 읽었는가
- 사용자가 한 사례에서 반복 패턴을 지적했다면 전체 산출물과 파생 파일을 같은 개념으로 다시 검색했는가
- 표면 요청만 처리하고, 사용자가 실제로 확인하려던 문제를 남겨두지 않았는가
- 사용자가 원한 최종 상태와 성공 근거를 설명할 수 있는가
- 모델이 판단할 수 있는 구현 선택을 불필요하게 사용자에게 되돌리지 않았는가
- 결과를 받은 사용자가 곧바로 다시 시킬 직접 필수 작업이 남아 있지 않은가
- 명시되지 않았더라도 직접 필요하고 저위험·가역적인 작업을 권한 안에서 처리했는가
- 행동이나 입력·출력 계약을 바꿨다면 구현, 공개 스키마, 예시, 문서, 테스트가 새 의미를 실제로 보여주며, 새 사용자 입력 표현을 공개 예시 하나 이상이 사용하는가
- 저장소의 지도·색인·계약이 현재 목적과 연결된 검증된 근거나 기회를 가리켰다면 필요한 최소 범위까지 확인했는가
- 검증된 개선폭이 크고 저비용·저위험·가역적인 기회를 산문형 완료 보고에서 누락하지 않고, 근거·기대효과·비용·위험·최소 가역 실험의 구체값을 각각 보존했는가
- 위험의 영향 경계와 무엇을 어느 범위에서 검증할지 정한 최소 가역 실험을 서로 구분했는가
- JSON 전용, 고정 스키마, 본문 전용처럼 엄격한 출력 계약을 선택적 설명으로 오염시키지 않았는가
- 핵심 선택·추가 권한·비용이 필요한 남은 작업은 그 경계를 밝혔는가
- 주도성을 이유로 선택적 개선이나 무관한 정리까지 범위를 넓히지 않았는가
- 처음 받는 사람이 이 결과물만 보고 의미, 사용 방법, 남은 제약을 이해할 수 있는가
- 만든 사람의 의도는 살리고, 받는 사람의 경험에서 깨지는 부분은 없는가
- 실행하지 못한 검증이 있다면 이유를 적었는가
- 새 폴백, 분기, 테스트가 실제 실패 모드나 공개 계약을 설명하는가
- 불안감이나 리뷰 방어를 위해 고정한 테스트를 제거했는가
- 기준 원본, 실행 진입점, 검증 경로가 같은 모델을 따르는가
- 보이는 인터페이스만 맞추고 완료로 판정한 부분이 없는가
- 여러 턴·중단·위임에 걸친 목표라면 목적, 제약, 현재 소유권, 완료 근거가 재개 가능한 상태로 남아 있는가

## 단순화 검토

- 초보자가 이해하는가
- 전문가가 봐도 틀리지 않는가
- 예외 상황에서도 무너지지 않는가
- 핵심 목적이 더 빨리 달성되는가
- 설명은 짧아졌지만 판단은 더 쉬워졌는가

## 시각·웹 산출물 추가 검토

- 브라우저 전체 폭이 아니라 실제 게시 컨테이너 폭에서 확인했는가
- 목표 데스크톱, 중간 CMS 폭, 좁은 모바일 폭을 렌더링하고 검사 폭을 기록했는가
- 긴 한국어 복합어, 숫자·단위·비교어, 출처 레이블에서 잘림·겹침·가로 넘침이 없는가
- 숫자와 `이상·이하·초과·미만`처럼 하나의 의미 단위가 버튼이나 배지처럼 분리되지 않았는가
- 기계 검사와 별도로 최종 스크린샷을 사람이 읽었는가
- HTML, CMS용 코드, 미리보기가 같은 최종 내용을 사용하며 마지막 수정 뒤 다시 생성됐는가
