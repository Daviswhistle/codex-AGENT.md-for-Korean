# 대용량 컨텍스트 프론티어 모델 도입에 따른 스킬 절차 유연화

날짜: 2026-09-05

결정: GPT-6 Astra 등 100만 토큰 이상의 대용량 컨텍스트와 향상된 에이전틱 역량을 갖춘 차세대 프론티어 모델 도입에 맞춰, `translation-quality`의 기계적 3,000단어 청킹 강제를 모델 용량 기반 조건부 청킹으로 완화하고, `prompt-migration.md`를 일반 프론티어 모델 이행 가이드라인으로 확장하며, 고단가 프론티어 모델과 비용 효율적 실행 워커 간의 역할 경계를 명확히 유지한다.

배경: 과거 GPT-5.6 이하 세대 모델의 장문 환각, 누락, 출력 길이 한계를 극복하기 위해 `translation-quality` 등에 3,000단어 단위 강제 청킹, `work/` 파일 분할, 스크립트 기반 수동 머지 절차가 도입되었다. 그러나 1.05M 토큰 컨텍스트와 높은 장문 일관성을 제공하는 최신 프론티어 모델 환경에서는 수천 단어 수준의 문서를 억지로 분할하고 재조립하는 절차가 오히려 불필요한 도구 호출과 고단가(입력 $10 / 출력 $50) 토큰 낭비를 유발한다. 한편, 전역 지침의 모델 중립성 원칙과 독립적 품질 검수 게이트(용어 원장, 개념 검수, HTML/수치 QA)는 유지되어야 한다.

경계:

1. `translation-quality`에서 단일 패스 직접 생성을 선택하더라도 용어 원장(terminology ledger), 개념 검수, 수치 대조, HTML QA 등 핵심 품질 게이트는 생략하지 않는다.
2. 활성 모델의 신뢰할 수 있는 단일 패스 용량을 초과하거나 장문 누락 위험이 있는 경우, 기존의 청크 분할 및 결정론적 조립 워크플로를 안전망으로 유지한다.
3. 고단가 프론티어 모델(GPT-6 Astra 등)은 제품 의도 해석, 전략적 아키텍처 판단, 고난도 검토 등 주 세션에 우선 투입하며, 경계가 명확한 실행 워커에 습관적으로 투입하지 않는다.
4. 전역 `AGENTS.md`의 모델 중립적 철학과 행동 권한은 수정하지 않는다.

대안:

1. 기존 청킹 및 머지 스크립트, 청크 파일 체계를 완전히 삭제한다: 구형 모델이나 수만 단어 이상의 초대형 문서에서 복구 수단이 사라지므로 기각.
2. 모델이 바뀌어도 3,000단어 기계적 청킹 절차를 그대로 유지한다: 차세대 모델의 대용량 컨텍스트 이점을 살리지 못하고 고비용 토큰과 도구 호출을 낭비하므로 기각.
3. 전역 `AGENTS.md`에 GPT-6 Astra 전용 규칙을 추가한다: 전역 지침의 모델 중립성 원칙(2026-07-16 결정)을 위반하므로 기각.

이유: 모델이 발전함에 따라 이전 세대의 한계를 방어하기 위해 만들어진 복잡한 우회 절차(과도한 단계 지정, 기계적 파일 분할)를 가지치기하는 것은 키트의 핵심 철학("필요한 것을 잃지 않는 가장 단순한 형태를 찾는다", "불필요한 것은 제거한다")에 부합한다. 동시에 성공 기준과 품질 게이트를 온전히 보존함으로써 단순화 후에도 안전성과 산출물 품질을 보장한다.

나중에 다시 볼 조건:

- 실제 대표 과제에서 대용량 컨텍스트 단일 패스 생성이 장문 누락이나 왜곡을 반복적으로 일으킬 때
- GPT-6 계열의 비용 효율적인 하위 워커 모델(예: 경량 버전)이 출시되어 실행 워커 기본 후보를 재편성할 때
- OpenAI Responses API의 네이티브 도구 규약이 키트 런타임에 직접 통합될 때
