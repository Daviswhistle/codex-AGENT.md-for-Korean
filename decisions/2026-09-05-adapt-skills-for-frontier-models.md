# 프론티어 모델 이행: 절차는 단순화하고 검증 계약은 보존

날짜: 2026-09-05

## 결정과 근거

GPT-6 Astra 도입에 맞춰 지침의 중복과 실행 경로의 불일치를 정리한다. 전역 철학과 모델 중립성은 유지한다. 모델 사양과 이행 조건은 `guidelines/prompt-migration.md`에 확인일·1차 출처와 함께 모으고, 실제 적용은 활성 런타임으로 확인한다.

같은 날의 선행 변경 `0a60923bdb8cafbc1ff13097a2fdc246629c5a44`는 고정 3,000단어 청킹을 조건부 청킹으로 바꿨다. 방향은 유지하되, 큰 입력 컨텍스트를 충분한 출력 용량이나 무누락의 증거로 취급하지 않는다. 단일 패스에서도 필요한 원문 대조·QA 근거와 청크 전용 실행물을 분리한다.

## 변경 범위

1. 번역의 실행 모드 선택과 공유 QA는 항상 읽는 `translation-quality/references/core.md`를 원본으로 삼는다. 스킬 진입점은 호출·로딩·완료 계약에 집중하고 동일한 상세 절차를 반복하지 않는다.
2. 출력·도구 예산, 구조와 누락 위험에 따라 단일 패스 또는 실제 청크 생성을 선택한다. 둘 다 원문 위치 대조, 용어·수치·개념 검수와 최종 파일 QA를 유지한다. 단일 패스에서는 청크 폴더·진행 원장·병합만 생략하며, 실적발표 HTML QA의 `--chunks`도 실제 청크가 있을 때만 전달한다.
3. 소프트웨어 스킬 진입점에서 상세 자원 선택을 worker reference로 통합한다. Luna Max + Fast 우선 후보, 단일 writer와 안정된 reader, 주 세션의 검증 책임, CRA/TCA는 유지한다. 검증 범위는 실제 영향에 비례시키되 필수 검사를 생략하지 않는다.
4. 인수인계에서 유효한 이전 조회·실행 근거의 재사용을 허용하고 변경·근거 소실 시 재확인한다. 과거 실행을 현재 턴의 실행으로 표현하지 않는다. 문구 존재 검사를 행동 검증으로 취급하지 않는다.

## 보존과 제외

전역 `AGENTS.md`, 프로젝트 override, 설치 경로·manifest, 다섯 스킬의 이름과 설치 단위, 실행 helper와 테스트, 기존 평가 기록은 바꾸지 않는다. 번역 병합 도구는 장문·제한된 런타임의 복구 수단으로 남긴다. outcome-owner의 durable ledger, 권한·동시성·복구 안전장치와 CRA의 리뷰 근거는 모델이나 네이티브 문맥 기능만으로 대체하지 않는다.

새 모델을 모든 워커에 강제하거나, 가격만으로 역할을 제한하거나, 새 런타임·검증 프레임워크·상주 프로세스를 추가하지 않는다. 이 변경은 사용자 계정·설정을 수정하거나 push·배포 권한을 넓히지 않는다.

## 대안과 판단

기존 절차를 그대로 유지하면 조건부 청킹과 청크 전제 QA가 충돌하고 중복 지침이 계속 따로 변한다. 반대로 청크 helper·원문 대조·독립 검토를 삭제하면 출력 제한과 누락, 회귀에 대한 복구 수단을 잃는다. 따라서 실행 선택과 증거 요구를 분리하고, 상세 계약을 기존 reference로 통합한다.

지침이 짧아졌다는 사실은 비용이나 품질 향상의 실측 증거가 아니다. 먼저 기계 검증과 변경 diff를 확인하고, 같은 Astra 설정에서 선행 commit과 후보를 대표 과제로 비교한다. 필요한 모델 실행이나 독립 리뷰가 불가능하면 미실행으로 남기며 정적 검사 결과로 대신하지 않는다. 대표 과제와 기록 항목은 `guidelines/prompt-migration.md`에 둔다.

## 재검토 조건

출력 예산 판단 오류, 장문 누락, 오래된 근거 재사용, 필요한 검증 생략, 위임 품질 저하가 실제 실행에서 관측되거나, 모델·호스트의 출력·도구·문맥 계약이 바뀌면 영향을 받는 가장 작은 계약부터 다시 검토한다.
