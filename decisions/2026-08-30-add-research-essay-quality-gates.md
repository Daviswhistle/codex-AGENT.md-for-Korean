# 근거 기반 조사 에세이 품질 게이트 추가

날짜: 2026-08-30

결정: 모든 사용자 대상 답변에는 전역 최소 글쓰기 기준을 적용하고, 글쓰기 자체가 주요 품질 병목일 때 `writing-quality`의 전체 작성·검수 절차를 호출한다. 일반 질의응답이라는 형식은 호출 사유도 배제 사유도 아니다. 그 위에 장문·반복 근거 기반 조사 에세이용 프로필을 추가하고, 주제 원장·주장표·조건부 사건표·용어 및 출력 표면 계약을 초안 전 작업 묶음으로 정의한다. 사실 검수와 출력 언어별 편집은 서로 다른 검수 관점으로 분리하며, 시스코의 회계분기 누락, 짧은 출처 기반 답변의 과적용, 시간축 없는 원고의 사건표 강제, 영어 원고의 편집기 오선택을 대표 회귀 사례로 남긴다.

## 배경

실제 반복 조사 글에서 다음 실패가 함께 나타났다.

1. 과거 글과 다른 사례를 골랐지만 핵심 메커니즘이나 최종 교훈이 겹쳤다.
2. 자료와 출처는 많이 찾았지만 초안 이전에 시간축을 고정하지 않아 서로 다른 회계분기의 수치를 직접 연결했다.
3. 공식 공시가 확인한 사실과 후대 연구자의 설명 모형을 같은 확신도로 서술했다.
4. 영어 원문의 용어, URL, 이미지 표식과 도구 표면이 한국어 독자용 본문에 남았다.
5. 같은 작성자가 같은 맥락에서 자기 원고를 한 번 다시 읽는 절차만으로는 이미 머릿속에서 연결한 중간 단계를 본문에도 썼다고 착각하기 쉬웠다.
6. `일반 질의 응답이 산문이라는 이유만으로 호출하지 않는다`는 문구가 전체 절차의 비용을 제한하려는 의도와 달리, 일반 질의응답에는 글쓰기 품질 스킬이 필요 없다는 범주적 배제로 읽힐 수 있었다.

기존 `writing-quality`에는 사실·인과·장르 적합성·한국어와 영어에 관한 좋은 원칙이 있었지만, 반복 조사 에세이를 채팅 답변으로 오인해 호출하지 않을 수 있었고, 날짜·분기·전망과 실적을 초안 전에 구조화하는 필수 작업물과 분리 검수 경로가 없었다. 동시에 전역 지침에는 모든 사용자 대상 답변이 지켜야 할 최소 글쓰기 기준이 명시적으로 분리돼 있지 않았다.

초기 구현을 검토한 결과 다음 경계도 명시적으로 고정할 필요가 확인됐다.

- 단순히 출처를 사용한다는 이유만으로 짧은 답변에 무거운 조사 프로필을 적용하면 안 된다.
- 사건표는 날짜·기간·순서·변화 주장이 있을 때만 필요하다.
- 한국어 전용 편집기를 영어 원고에 적용하면 안 된다.
- `agents/openai.yaml`의 UI 메타데이터는 게시·설치 경로의 길이 계약을 정적 검증해야 한다.

## 선택한 구조

새 최상위 스킬을 만들지 않는다. 조사 에세이는 여전히 사용자 대상 글쓰기이므로 기존 `writing-quality` 안에 프로필로 둔다.

- `AGENTS.md`: 모든 사용자 대상 답변의 최소 글쓰기 기준과, 답변 형식이 아니라 글쓰기 난이도·오류 비용·퇴고 가치로 `writing-quality`를 호출하는 라우팅 계약
- `references/evidence-backed-research-essay.md`: 장문·반복 작업을 전제로 한 적용 조건, 완료 조건, 주제 원장, 다섯 줄 논리 설계, 주장표, 조건부 사건표, 언어별 용어·표면 계약, 분리 검수와 출고 중단 조건
- `agents/research_fact_reviewer.md`: 사실·연대기·수치·출처·인과만 보는 검수 관점. 사건표 필요 여부를 먼저 판정한다.
- `agents/korean_research_editor.md`: 사실 검수 뒤 한국어·구조·중복·표면 잔재만 보는 편집 관점
- `agents/english_research_editor.md`: 사실 검수 뒤 영어의 구조·용어·관용성·중복·표면 잔재만 보는 편집 관점
- `references/research-essay-evaluation.md`: 시스코 연대기, 동일 메커니즘 중복, 전망·관측·모형값 경계와 함께 짧은 답변·비시간축 원고·영어 원고의 라우팅 경계를 다루는 전향 평가
- `scripts/openai_yaml_contract.py`: 모든 스킬의 `agents/openai.yaml` 구조와 필수 필드, `short_description` 25~64자 계약을 검증하는 표준 라이브러리 기반 검사

`SKILL.md`의 호출 경계는 반복 발행되거나 장문인 근거 기반 조사 글을 채팅 표면에서도 원고로 취급하도록 넓힌다. 문장 형식만으로 무거운 전체 절차를 호출하지 않고, 짧은 답변이 출처를 사용한다는 사실만으로도 호출하지 않는다. 출력 언어를 먼저 확정한 뒤 한국어와 영어 편집기를 분기한다.

## 대안과 기각 이유

1. 전역 `AGENTS.md`에 주장표·사건표·분리 검수 같은 조사 절차 전체를 추가한다.
   - 모든 작업에 프롬프트 무게를 늘리고 장르별 절차를 전역화하므로 기각한다. 전역에는 모든 답변에 필요한 최소 글쓰기 기준과 라우팅 계약만 둔다.
2. 시스코에서 나온 표현만 금지하는 정적 테스트를 추가한다.
   - Markdown 문구를 얼리고 다른 연대기 오류를 잡지 못하므로 기각한다.
3. 작성자에게 더 주의해서 자기검수하라고만 지시한다.
   - 반복 실패를 개인 주의력에 다시 맡기며 `reproducible-quality` 원칙과 맞지 않으므로 기각한다.
4. 조사 전용 최상위 스킬을 추가한다.
   - `writing-quality`와 책임이 겹치고 라우팅이 더 복잡해지므로 기각한다.
5. 모든 조사 글에 빈 사건표를 요구한다.
   - 시간축이 없는 횡단면·개념 분석에 형식적 작업만 늘리므로 기각한다. 사건표 적용 여부와 이유를 먼저 판정한다.
6. 하나의 언어 중립 편집기로 한국어와 영어를 모두 검수한다.
   - 두 언어의 번역투·관용성·용어 문제를 같은 체크리스트로 정확히 잡기 어려워 출력 언어별 편집 관점을 둔다.

## 검증 계약

- 자동 검증은 manifest, frontmatter, 독립 설치 가능성, `agents/openai.yaml`의 기계 판독 가능한 메타데이터 계약, 기존 실행 테스트와 helper를 확인한다.
- `short_description`은 양 끝을 포함해 25~64자로 검증하며, 24자·65자와 이번에 발견된 71자 값이 실패하는 단위 테스트를 둔다.
- Markdown의 특정 문구를 동결하는 테스트는 추가하지 않는다.
- 행동 품질은 `research-essay-evaluation.md`의 대표 과제를 기준선과 후보에 같은 조건으로 실행해 평가한다.
- 시스코 평가에서는 세 분기의 연대기, 발표일과 대상 기간, 전망과 실제값, 회사 설명과 후대 모형의 증거 성격, 한국어 용어와 출력 표면을 각각 판정한다.
- 짧은 출처 기반 질의응답에는 프로필이 적용되지 않는지, 시간축 없는 조사 글은 사건표 `해당 없음`으로 통과할 수 있는지, 영어 원고는 영어 편집기를 선택하는지 별도 경계 과제로 확인한다.
- 기존 범용 과제를 다시 실행해 무거운 조사 프로필이 짧은 메시지·기술 설명·에세이에 과적용되지 않는지 확인한다.
- 일반 질의응답 사례에서도 전역 최소 글쓰기 기준이 유지되고, 답변 형식만으로 전체 스킬 호출 여부가 결정되지 않는지 확인한다.

## 나중에 다시 볼 조건

- 별도 검수 관점이 실제 실행에서 반복적으로 호출되지 않거나 비용 대비 개선이 작다.
- 작업 묶음이 형식적 표 채우기로 변해 조사와 글쓰기를 방해한다.
- 주제 원장이 길어져 의미 비교보다 관리비용이 커진다.
- 여러 조사 에세이에서 동일한 기계적 오류가 누적되어 작은 helper가 수동 검수보다 더 정확하고 저렴해진다.
