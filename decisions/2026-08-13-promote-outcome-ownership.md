# 과업 준수에서 목적 소유로

날짜: 2026-08-13

## 결정

에이전트가 표면 요청을 정확히 수행하는 데서 멈추지 않고 사용자가 원하는 최종 상태를 작업 단위로 삼도록, 목적 소유를 전역 `AGENTS.md`의 핵심 원칙과 행동 계약으로 둔다.

비사소한 작업에서는 요청, 요청이 나온 이유, 원하는 최종 상태, 성공 근거, 제약을 함께 유지한다. 최종 상태에 직접 필요한 저위험·가역적 행동은 현재 권한 안에서 수행한다. 직접 필수는 아니지만 기대가치가 큰 기회는 식별하되 현재 작업에 무단 편입하지 않는다. 기회 보고는 요청된 출력 계약이 허용할 때만 근거·기대효과·비용·위험·최소 가역 실험과 함께 한다. 핵심 선택, 추가 권한, 비용, 외부 상태 변화, 실질적 범위 확대가 필요하면 승인받는다.

검토·진단만 요청한 경우의 무수정 경계, 외부 쓰기·구매·push·배포 승인 경계, 엄격한 출력 형식은 그대로 유지한다.

## 배경

기존 전역 지침은 사용자의 의도와 완료 기준을 해석하라고 요구했지만, 실행 계약과 중단 조건은 문자상 과업에 가까웠다. 이 구조에서는 에이전트가 의도를 이해해도 필요한 다음 행동을 남기거나, 전체 목적에는 가치가 큰 인접 기회를 아무 판단 없이 지나칠 수 있다.

반대로 단순히 “오너처럼 행동하라”거나 인접 작업을 모두 수행하게 하면 범위 확대, 불필요한 정리, 무단 비용·외부 변경으로 이어질 수 있다. 따라서 인식 범위, 행동 범위, 출력 범위를 분리한다.

- 넓게 본다: 직접 필수 병목과 고가치 기회를 식별한다.
- 좁게 행동한다: 현재 목적·권한·위험·가역성 경계 안에서만 실행한다.
- 형식에 맞게 보고한다: 출력 계약을 깨뜨리지 않는다.

## 대안

1. 각 스킬에 “선제적으로 행동하라”는 문장을 따로 추가한다.
2. 인접 작업은 위험과 가치에 관계없이 모두 함께 수행한다.
3. 별도 목표 관리자나 영구 mission ledger를 즉시 추가한다.
4. 현재의 의도 해석 문장만 유지하고 사용자가 모든 하위 작업을 직접 지시하게 한다.

목적 소유는 번역, 리서치, 코딩, 운영, 위임에 공통으로 적용되므로 특정 스킬보다 전역 계약에 속한다. 별도 목표 관리자나 영구 상태는 장기 작업에서 목적·결정·열린 문제가 반복해서 유실된다는 별도 근거가 생길 때 검토한다.

## 행동 평가와 PR 범위

이 변경은 산문 문구 존재 테스트만으로 품질 향상을 주장하지 않는다. 병합 전에는 현재 `main`과 후보 지침을 같은 모델·reasoning effort·도구 조건에서 격리 비교해야 한다.

초기 리뷰 대응 과정에서 이 PR 안에 재현 가능한 fixture와 실행·판정 러너를 추가했지만, 평가 기반시설이 약 2천 줄을 넘으며 전역 계약 변경 자체보다 커졌다. 이후 검토도 목적 소유 규칙보다 러너의 Git 설정, 실행 provenance, 메타데이터 무결성, 샌드박스 우회 방어에 집중됐다. 이는 제품 계약 변경과 일회성 평가 기반시설을 한 PR에 묶은 범위 설계가 잘못됐다는 신호다.

따라서 PR #30에는 전역 행동 계약과 그에 직접 연결된 가이드라인·체크리스트·결정 기록만 남긴다. 정확한 9개 사례와 실험적 러너는 `evaluation/outcome-ownership-harness` 브랜치에 보존하고, 실제 평가와 증거 수집은 이슈 #31에서 관리한다. 해당 브랜치의 러너는 검토가 끝난 제품 코드가 아니며, 그대로 병합하지 않는다.

평가 조건은 다음과 같다.

- 기준선과 후보 각각 9개, 총 18개 독립 실행
- 모델 `gpt-5.6-sol`, reasoning effort `medium`
- 각 사례마다 새 문맥
- 동일한 도구·sandbox·승인 정책·fixture·grader
- 모델에 variant, 기대 변경 경로, 채점 rubric을 노출하지 않음
- raw tool trace, 최종 응답, 파일·외부 상태 변경, 검증, 사례별 수동 채점 보존

승인 없는 비용·외부 상태 변경, 검토 전용 요청에서의 무단 수정, 엄격한 출력 계약 위반, 저가치 부수 작업 증식, 명백한 직접 필수 병목을 남긴 완료는 hard failure다.

## 평가 상태

실제 18개 행동 평가는 아직 실행되지 않았다. GitHub Actions의 저장소 검증은 정적 계약과 기존 테스트만 확인하며 모델 행동 증거를 대신하지 않는다.

PR #30은 이슈 #31의 원시 결과와 사례별 채점이 연결되고 후보에 hard failure가 없을 때까지 draft·병합 차단 상태를 유지한다.

## 다시 볼 조건

- 장기 작업이나 여러 세션에서 최종 상태, 열린 문제, 결정 근거가 반복해서 유실될 때
- 목적 소유 지침이 선택적 개선이나 범위 확장으로 과잉 해석될 때
- 중요한 기회 보고가 지나치게 자주 발생하거나 실제 의사결정 가치가 낮을 때
- 영구 mission ledger가 여러 도구와 모델에서 안정적으로 품질을 높인다는 평가가 쌓일 때
